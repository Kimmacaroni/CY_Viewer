# 개인 Google Drive 동기화

## 구성

- Google Cloud 프로젝트 `cy-viewer`, Firebase Spark 유지, 결제 연결 없음.
- Google Drive API 사용. Firebase Storage/Firestore에는 PDF나 읽기 상태를 저장하지 않는다.
- 웹: Google Identity Services token model, 승인 출처 `https://kimmacaroni.github.io`.
- Mac/Windows: 데스크톱 OAuth, 시스템 브라우저 + 임의 포트의 127.0.0.1 callback, state 및 PKCE S256.
- 공개 클라이언트 ID만 소스에 둔다. 토큰, 인증 코드, 웹 클라이언트 secret을 저장소나 로그에 기록하지 않는다.
- `drive.file` 범위만 요청한다. 사용자가 연결하기 전에는 업로드하지 않으며, 연결 후 여는 PDF부터 동기화한다.
- 현재 세션의 토큰만 메모리에 보관한다. 재실행/만료 후 재연결이 필요하다.

## 데이터와 충돌

- PDF 내용 SHA-256을 `appProperties.cyHash`, 앱 표시를 `cyViewer=1`로 둔다.
- 같은 PDF를 다시 열 때 원본을 재업로드하지 않는다. 다운로드 후 해시를 검증한다.
- description의 JSON `v=1`, `page={n,at}`, `marks={페이지:{on,at}}`를 세 플랫폼이 공유한다. 페이지는 1부터 시작하며 at은 Unix 밀리초다.
- 쪽별 책갈피 변경 시각으로 병합하므로 다른 기기의 별도 책갈피가 사라지지 않는다. 읽던 페이지는 가장 최근 변경을 적용한다. 기기 시계가 크게 어긋나면 최신 판정에도 영향이 있다.
- ETag가 제공되면 If-Match 조건부 저장을 사용하고 충돌 시 다시 읽어 최대 3번 병합한다.
- 목록은 최근 수정 순서 최대 5개이며 오래된 PDF를 자동 삭제하지 않는다. 개인 Drive에서 관리한다.
- 연결 해제는 저장된 원본을 삭제하지 않는다. 새 계정에 이전 계정 작업이 적용되지 않도록 실행 세대를 분리한다.
- 네트워크 실패는 로컬 PDF 사용을 막지 않는다. 실패한 상태 변경은 현재 세션에서 다음 저장 때 재시도한다. 앱을 닫기 전 동기화 완료 상태를 확인한다.

## 검증과 제한

- 단위 테스트: 동시 책갈피 추가/삭제 병합, 로그아웃 후 늦은 응답 차단, 중복 업로드 방지, 최근 5개, 다운로드 무결성, 충돌 재시도.
- 실제 Google 권한 동의, 다른 계정 및 iPhone/iPad 홈 화면 웹앱의 로그인 복귀는 별도의 실제 환경 검증이 필요하다.
- 초기 로컬 문서함 전체를 자동 업로드하지 않는다. PDF 편집 결과의 자동 업로드는 지원 범위가 아니며 저장한 PDF를 다시 열면 새 내용 해시로 구분된다.
