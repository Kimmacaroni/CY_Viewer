# 웹 PDF 회색 화면 대응

2026-09-27 iPhone Safari에서 파일명만 표시되고 PDF 영역이 회색으로 남는 현상이 보고됐다.

## 확인한 사실

- 배포된 PDFium WASM 경로는 HTTP 200과 `application/wasm`으로 응답했다.
- pdfrx 2.6.1의 PdfViewer는 초기화를 기다린 뒤 문서 로드 리스너를 연결한다. 따라서 엔진 초기화 실패는 기존 문서 오류 배너만으로 처리되지 않는다.
- PDFium 클라이언트의 worker 오류 처리는 로그만 남기므로 초기화 요청이 끝나지 않을 수 있다.
- 특정 iPhone의 실패 원인은 아직 확정하지 못했다. 원본 PDF와 실제 Safari 오류 로그를 확보하지 않은 상태다. 최신 pdfrx 변경 내역에도 이 현상을 해결한다고 명시된 수정은 확인되지 않았다.

## 변경

- 웹 리더가 PDFium 초기화를 명시적으로 기다리고 예외를 처리한다. 초기화 전 PdfViewer를 만들지 않는다.
- 엔진 초기화부터 문서 준비까지 45초 동안 응답이 없으면 복구 화면을 표시한다.
- 초기화 이후에는 PDF 뷰어의 로딩·문서 오류 화면을 가리지 않는다.
- 로딩·실패 화면과 문서 도구에서 브라우저 기본 PDF 뷰어를 열 수 있다. 선택한 바이트로 로컬 Blob URL을 만들며 파일을 서버에 업로드하지 않는다. URL은 10분 후 해제한다.
- macOS와 Windows 네이티브 앱 코드는 변경하지 않는다.

## 검증

- Flutter 분석 통과, 기존 17개와 로딩 회귀 5개 테스트 통과.
- 회귀 검증: 초기화 대기/실패, 늦은 응답, 준비 완료 시 타이머 취소, 문서 준비 시간 초과, 화면 종료 후 예외 처리.
- iPhone Safari 실제 PDF 렌더링과 새 탭 열기는 아직 미검증이다. Chrome 확장 프로그램 UI가 자동화를 차단했다.
