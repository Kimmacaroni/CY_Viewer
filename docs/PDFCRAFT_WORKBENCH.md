# PdfCraft PDF 도구 확장

Mac 1.13.0+20·Windows 1.10.0에서 문서를 연 뒤 **PDF 도구**를 사용한다. 이전 버전의 추출·병합만으로는 부족하다는 사용자 요청에 따라 실제 편집·문서 관리·보안 기능을 확대했다. Mac 기본 800×600 창에서도 상단 이름 있는 버튼으로 연다.

## 실제 제공 기능

| 작업 | Mac | Windows |
| --- | --- | --- |
| 페이지 회전·삭제·빈 A4 페이지 삽입 | 선택 목록에서 실행 | 작업과 페이지 범위 입력 |
| 페이지 재정렬·추출 | 드래그·선택 추출 | 페이지 추출·병합에서 순서 입력 |
| 여러 PDF 병합 | 추가 목록 이동·삭제 | 기존 페이지 추출·병합 화면 |
| 페이지 편집 되돌리기·다시 실행 | 최근 30단계 | 제공하지 않음 |
| 일정 쪽 수마다 분할 | PDF들을 담은 ZIP 저장 | 동일 |
| 제목·작성자·주제·키워드 편집 | 정보·책갈피 탭 | 문서 정보 작업 |
| 실제 PDF 책갈피 추가·이름/대상 변경·삭제 | 기존 계층 유지, 새 루트 책갈피 추가 | 책갈피와 작업 선택 |
| AES-256 암호 설정·변경·해제 | 보안 탭 | 출력 보안 선택 |
| 저장 후 결과 열기 | 완료 영역의 결과 열기 | 기존 PDF 열기로 선택 |

웹·iPhone에는 이 로컬 실행 모듈을 연결하지 않는다. OCR·본문 텍스트 편집·전자서명 생성 등 PdfCraft의 다른 기능 전체를 이식한 것은 아니다.

## 사용과 데이터 처리

Mac은 페이지 편집 → 합치기·분할 → 정보·책갈피 → 보안의 네 탭에서 작업을 조합하고 한 번에 새 파일로 저장한다. 페이지 범위는 편집 전 원본의 번호다. 빈 페이지는 마지막 선택 페이지 뒤에 삽입한다. 책갈피 대상도 원본 번호로 입력하며, 순서를 바꾸면 내부 링크·책갈피 목적지를 함께 옮긴다. 제거된 페이지의 링크 처리는 PdfCraft의 문서 결합 규칙을 따른다.

원본은 덮어쓰지 않는다. Mac의 임시 화면 텍스트 표시는 이 도구 결과에 포함되지 않음을 화면에 안내한다. Windows는 현재 문서 사본을 사용한다. 제목 등 문서 정보와 PDF 내장 책갈피는 새 PDF 내부에 기록하며 CY뷰어의 별도 개인 책갈피 목록과 구별한다.

암호 PDF는 소유자 권한을 확인하고, 새 암호 설정 또는 암호 해제를 명시적으로 선택해야 한다. 새 암호는 열기·소유자 암호에 함께 쓰며, 기존 권한을 보존하는 모드는 아니다. 분할 시 모든 PDF에 새 암호를 적용한다. 암호는 로컬 프로세스의 표준 입력으로 전달하고 명령행·로그·환경변수에 넣지 않는다. 전자서명 문서는 변경을 거부한다.

PdfCraft 고정 커밋은 기존 `d9607ec3befcda3e78062ceb5e54b97563aedad1`이며 `cos`의 암호 처리·문서 저장과 `organize`의 페이지·정보·책갈피·분할 API를 활용한다. 암호화 난수는 운영체제의 난수로 만든다. `cy-pdfcraft 0.2.0`을 앱에 동봉한다. MIT·제작자 고지와 실제 배포 대상 의존성 고지를 유지한다. 서버로 문서를 전송하지 않는다.

## 검증

- 독립 PDF 엔진(PyMuPDF) 회귀 8개: 추출·병합, 페이지 픽셀·텍스트·주석·폼·링크 보존, 회전·빈 페이지·삭제·목적지 이동, 한글 정보·내장 책갈피 편집, 분할 ZIP, AES-256 설정·변경·해제·암호화 분할, 소유자 권한·잘못된 요청·원본 보호.
- Flutter UI: 좁은 화면·큰 글자, 회전·빈 페이지·되돌리기가 저장 요청에 반영되는지, 정보·책갈피 저장 및 오류 후 재시도 검사.
- Windows GUI smoke: 실제 대화상자로 재정렬 PDF·회전 PDF·분할 ZIP 저장 후 재열기. 로컬 Linux Tk 검사와 Windows Actions 실행을 구분한다.
- Mac 샌드박스: 실제 배포 모듈 실행 후 PDFKit으로 순서·회전·빈 페이지·문서 정보·책갈피·암호 재열기 검사. Mac 앱 빌드와 기본 창 진입점 검사도 실행한다.

공개 배포 검증 결과는 아래에 기록한다. 사용자 Mac에서 직접 설치·저장창을 클릭했다고 주장하지 않는다.

최종 로컬 검증 결과: Flutter 분석 문제 없음, 실제 PDFium·리더 암호 경로를 포함한 전체 61개 통과·Mac 전용 2개 제외. Windows 단위 검사 20개·PDF 독립 엔진 검사 8개·다운로드 사이트 검사 4개 통과. Rust 테스트·Clippy 통과. Linux Tk에서 새 회전 PDF와 분할 ZIP의 저장·재열기 통과. Mac 업데이트 Swift 검사와 샌드박스 검사는 해당 OS의 Actions에서 수행한다.

추가로 실제 Flutter 서비스→PdfCraft→PDFium 경로에서 암호 PDF를 생성·검사하고, 암호 해제와 분할 ZIP 재열기를 확인했다. `macos_app/test/pdfcraft_runtime_test.dart`는 `CY_PDFIUM_TEST_LIBRARY`와 빌드된 모듈을 지정해 실행한다. 기본 800×600 창에서 회전·삭제·빈 페이지 도구가 스크롤 없이 보이는지 검사한다.

암호가 걸린 PDF는 리더의 마스킹된 암호 입력창으로 연다. 잘못된 암호는 다시 입력할 수 있고, 성공한 암호는 현재 문서의 메모리에서 PDF 도구로 전달한다. 저장·최근 목록·로그에는 보관하지 않는다. 실제 PDFium 리더에서 잘못된 암호→재입력→열기 성공 경로도 확인했다.

Windows도 문서 열기의 암호 입력·잘못된 암호 재입력·취소 시 기존 문서 유지와 PDF 도구로의 메모리 암호 전달을 지원한다. 실제 Tk 리더→PDF 도구→암호 해제 사본 저장·재열기를 검사했다.

## 공개 배포 확인 (2026-10-15)

[PR #32](https://github.com/Kimmacaroni/CY_Viewer/pull/32)를 `5aefe40cf372ad040d0ac01b5f64c218333bfc6c`에 병합했다. Windows 출시 빌드 `38675182363`과 Mac 출시 빌드 `38675178985`에서 설치 파일을 게시했다.

- Mac: `CYViewer-macOS-v1.13.0.dmg`, 36,147,794바이트, SHA-256 `ac511459e3139948a330edeb0259d4a39e9d804aed45fa3ca19d57e171fedc07`. 공식 공개 파일을 직접 내려받아 릴리스 메타데이터·체크섬과 대조했다.
- Windows: `CYViewer-Setup-v1.10.0.exe`, 37,455,988바이트, SHA-256 `2892cfcac1ed2fa228eb8b1557ebcfcd05e5fbb4721b9c8bc4180aee1389c2ec`. 공식 공개 파일을 직접 내려받아 릴리스 메타데이터·체크섬과 대조했다.

Windows 출시 빌드에서 PDF 독립 엔진 8개·단위 검사 20개, 실제 GUI의 재정렬·회전·분할 ZIP·암호 재입력·해제 저장, 설치·재설치·설치 모듈 해시·실행 검사가 통과했다. Mac 출시 빌드에서 Flutter 분석·테스트, 앱 빌드·서명, 샌드박스 모듈의 순서·회전·빈 페이지·문서 정보·책갈피·암호 PDFKit 재열기 검사가 통과했다.

공개 웹 `1.13.0+20`과 캐시 식별자 `pdfcraft-workbench-1.13.0-20`을 확인했다. 실제 공개 Chrome에서 PDF 열기·페이지 이동·두 쪽 보기·책갈피 목록 진입이 통과했다. 웹에 데스크톱 PDF 도구를 제공한다고 표시하지 않는다.

Mac DMG 내부의 버전·빌드 번호, PDF 도구의 새 탭·암호 입력 연결과 `cy-pdfcraft 0.2.0`·제작자/의존성 고지를 확인했다. 사용자 Mac 설치 상태는 직접 확인하지 않았다. ⌘Q로 기존 앱을 종료하고 새 DMG의 CYViewer.app으로 Applications 앱을 교체한 뒤 다시 연다. PDF를 연 후 상단 **PDF 도구**를 사용한다.
