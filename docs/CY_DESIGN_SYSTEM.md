# CY뷰어 디자인 시스템

## 범위와 기준

Windows 배포본(`native_windows/cy_viewer.py`), macOS·iOS 앱(`macos_app/lib/app.dart`),
웹앱(`macos_app/lib/web_main.dart`)을 같은 문서 작업 공간으로 정돈한다.
기존 파란 강조색과 한국어 UI, 플랫폼별 파일 열기 동작을 기준으로 직접 개선한다.
`personal_pdf_viewer`는 초기 Flutter 프로젝트이며 현재 Windows 설치본의 진입점이 아니다.

## 조사와 선택 근거

2026-09-26 실제 웹앱과 소스를 검토했다. 웹앱은 화면 중앙의 작은 카드에
정보가 모이고, macOS 문서함은 즐겨찾기 상태가 아이콘으로만 드러난다.
Windows 도구막대는 검색과 보기 도구가 한 줄에 있어 작은 창에서 잘릴 수 있다.
Refero 스타일 검색은 구독 비활성 응답으로 사용할 수 없었다.
따라서 Refero 플러그인의 `typography.md`, `color.md`, `craft-details.md`와
기존 제품을 근거로 개선한다. 외부 브랜드를 복제하거나 온라인 사례를 봤다고 주장하지 않는다.

## 고정할 방향

- 중립적인 문서 작업 공간. 파란 주요 버튼 하나가 다음 행동을 안내한다.
- 표면은 얇은 경계로 구분하고, 장식용 그라데이션·과도한 그림자·가짜 문서 미리보기는 사용하지 않는다.
- 문서 썸네일을 가짜로 만들지 않는다. 실제 파일명·최근 열람·읽던 페이지를 제공한다.
- 색상만으로 상태를 전달하지 않는다. 오류·선택·저장 결과에는 텍스트를 함께 사용한다.
- Safari의 실제 HTML 파일 선택 입력과 네이티브 파일 접근·OCR·저장 로직은 보존한다.

## 상태와 반응형

- 빈 문서함: PDF 열기와 로컬 저장 안내. 즐겨찾기 빈 상태는 필터 해제 경로 제공.
- 최근 문서: 파일명 우선, 마지막 페이지와 열람 날짜는 보조 정보.
- 파일 여는 중: 진행 표시와 중복 열기 차단.
- 오류: 읽을 수 있는 대비, 다시 선택할 방법, 보조 기술 알림.
- 읽기: 좁은 화면에서는 추가 기능을 문서 도구 메뉴에 유지.
- 저장: 기존 성공·오류 메시지 유지. 원본과 내보내기 사본을 혼동시키지 않음.
- 모바일·큰 글자: 가로 배치가 충분하지 않으면 세로로 쌓고 스크롤 허용.

## 검증

Flutter 분석·기존 회귀 테스트, 좁은 화면/큰 글자 레이아웃 테스트,
웹 빌드와 실제 브라우저 렌더링을 확인한다. Windows는 구문 검사와 가능한
환경의 실행 검증을 구분해 보고하며, macOS에서 Windows 실행 완료로 보고하지 않는다.

## 플랫폼 공통 화면 구조

- 시작: 같은 제목 ‘문서를 열고, 바로 읽으세요.’, 기능 안내, ‘어떤 문서를 읽을까요?’ 카드와 ‘PDF 열기’ 주요 버튼을 쓴다. Windows도 문서를 열기 전에는 리더 도구를 숨긴다.
- 데스크톱 리더: 왼쪽 252px 패널을 문서 탐색 → 선택·편집 → 저장·내보내기 순서로 배치한다. Mac과 웹은 `CyReaderWorkspace`를 공유하고 Windows도 동일한 그룹과 폭을 쓴다.
- 작은 화면: Flutter는 1100px 미만 또는 큰 글자 설정에서 패널을 접고 상단 ‘문서 도구’로 접근한다. Windows도 1100px 미만에서는 상단 문서 도구로 패널을 여닫으며 기존 최소 창 크기와 패널 스크롤을 유지한다.
- 앱 문서함·OCR·이미지 저장과 웹의 공유 등 실제 지원 기능은 유지한다. 기능 차이를 숨기기 위해 작동하지 않는 버튼을 만들지 않는다.
- 파일 선택 대화상자와 인쇄 창은 각 운영체제의 기본 UI를 유지한다. 세 플랫폼 모두 같은 밝은·어두운 색상 토큰을 사용한다. Windows는 시작 시 운영체제 테마를 따른다.

## 배포 사이트 기준

기존 CY뷰어 디자인 시스템을 주 기준으로 직접 구현한다. Refero 온라인 자료는 구독 제한으로 조회하지 못했으며 내장 craft-details의 포커스·접근성 규칙을 따른다.
상단은 OS별 추천 다운로드를 첫 행동으로, 아래는 모든 플랫폼 다운로드와 업데이트 절차를 제공한다.
기존 앱 아이콘과 실제 Flutter 문서함 렌더 이미지를 사용하고, 가짜 문서나 사용 지표는 추가하지 않는다.
파랑은 주요 다운로드, 중립색은 플랫폼 선택과 도움말에 사용한다. 웹앱은 설치 파일처럼 표시하지 않고 ‘열기’와 홈 화면 추가를 안내한다.
기존 웹앱/PWA 경로를 보존하기 위해 배포 사이트는 `/download/`에 둔다.

## 다국어 표시

기존 CY뷰어를 시각 기준으로 유지한다. Refero craft-details의 명확한 입력 레이블과 최소 터치 영역을 적용해 언어 선택은 지구본 메뉴(앱)와 이름이 표시된 선택 상자(사이트)로 제공한다. 국기 아이콘으로 언어를 대신하지 않는다. 한국어·영어, 기기 언어 자동 선택을 제공하고 지원하지 않는 기기 언어는 영어를 사용한다. 문서 내용과 파일명은 번역하지 않는다. 긴 번역은 기존 반응형 배치에서 줄바꿈하며 기능을 숨기지 않는다.

## 최근 문서 5개

기존 문서함 목록과 Refero craft-details의 터치·포커스 원칙을 기준으로 파일명 중심의 행을 사용한다. 기본 화면에는 최근 5개를 최신순으로 표시하며 다시 열면 맨 위로 이동한다. Mac의 전체 문서·즐겨찾기는 별도 필터로 보존한다. 웹은 PDF 원본의 로컬 사본과 제거 버튼, 저장 위치 안내를 함께 표시한다. Windows는 시작 화면과 상단 최근 파일 메뉴에서 같은 목록을 제공한다. 이름이 길어도 주요 행동과 최대 5개 제한을 유지하며 가짜 썸네일은 만들지 않는다.

## 웹 인쇄 범위

기존 대화상자·입력 필드·주요 버튼을 사용해 전체/현재/직접 범위를 먼저 선택한다. 직접 범위는 `2-5, 8` 형식이며 오류를 입력 필드에 표시한다. iPad·Safari에서는 숨겨진 iframe 인쇄를 피하고 선택한 페이지의 벡터 PDF를 사용자의 두 번째 버튼 클릭으로 직접 연다. 원문 순서와 선택된 PDF의 쪽 수를 명시하고 원본을 수정하지 않는다.

## 웹 전체 페이지 기본 인쇄

기존 CY 대화상자를 시각 기준으로 고정하고 Refero craft-details의 명확한 상태·입력 원칙을 적용한다.
인쇄를 열 때 전체 페이지를 자동으로 준비하고, 준비 진행률과 전체 쪽 수를 표시한다.
주요 행동은 인쇄, 보조 행동은 범위 변경·닫기다. 준비가 끝나기 전 인쇄는 비활성화한다.
원본 PDF 외부 열기는 실패 시 사용자가 선택하는 보조 경로이며 자동으로 실행하지 않는다.

## 웹 브라우저 기본 입력

기존 색상·버튼 위치·52px 파일 입력과 최소 48px 인쇄 버튼을 유지한다.
브라우저의 실제 input/button을 Flutter 렌더링 레이어 밖에 배치하되 Flutter에서 계산한 위치와
스크롤 클립에 맞춘다. 다른 대화상자 뒤의 버튼은 숨기며 비활성 버튼은 HTML disabled로 표시한다.
Refero craft-details의 실제 포커스 유지 원칙에 따라 브라우저 기본 포커스 표시를 제거하지 않는다.

## 개인 Drive 연결

기존 CY뷰어 토큰과 문서함을 주 기준으로 유지한다. Refero 실시간 검색은 구독 제한으로 이용하지 못했으며 내장 craft-details의 명확한 권한 안내, 상태 표시, 포커스 원칙을 적용한다.
문서함의 구름 아이콘/Windows 메뉴에서 연결 계정, 최근 5개, 새로고침과 연결 해제를 한 화면에 제공한다. 연결 전에는 이후 여는 PDF가 개인 Drive에 전송됨을 명시하고, 오류·빈 목록·동기화 완료를 텍스트로 구분한다. 웹 로그인은 기존 파일 입력과 같은 실제 HTML 버튼 경로를 사용한다.

## Mac 기준 문서함 통일 (2026-09-28)

실제 설치된 Mac 앱의 문서함을 기준으로 제목·설명·최근/전체/즐겨찾기 필터·문서 아이콘·별 표시를 통일한다. Mac과 웹은 같은 `CyLibraryToolbar`를 사용한다. 웹의 넓은 화면에서는 PDF 열기를 상단에 두고 작은 화면에서는 파일 선택 영역을 본문에 유지한다. Windows는 같은 색상과 간격, 선택 필터의 체크 표시, 시작 화면의 소개/파일 선택 카드, 문서함 돌아가기를 제공한다.

운영체제 기본 파일 선택·인쇄와 각 플랫폼의 실제 저장 기능을 보존한다. 웹과 Windows의 전체/즐겨찾기는 기존 최근 5개 보관 목록 안에서 전환한다. Mac의 전체 로컬 문서 보관 방식은 유지한다. 즐겨찾기 없는 상태에는 전체 문서로 돌아가는 행동을 제공한다. 긴 파일명과 버튼명은 줄바꿈 또는 말줄임으로 주요 행동을 가리지 않는다. Windows의 즐겨찾기와 읽던 페이지는 원본 PDF와 별도로 로컬 메타데이터에 저장한다.

## 문서함과 리더 위계 정리 (2026-10-06)

사용자의 디자인 개선 요청에 따라 기존 CY뷰어 미리보기와 현행 코드를 주 기준으로 고정했다. Refero 스타일 조회는 NO_SUBSCRIPTION으로 사용할 수 없어 내장 typography의 작업 도구 밀도·위계 원칙과 craft-details의 포커스·터치 영역 기준을 참고했다.

| 결정 | 근거 | 적용 |
| --- | --- | --- |
| 반복 사용에서 최근 문서를 우선 | 기존 문서함 및 사용자 요청 | 첫 최근 문서에 이어서 읽기 표시, 실제 파일명과 날짜·페이지 유지 |
| 소개 영역 축소 | 기존 빈 상태 미리보기의 큰 2열 소개 | 하나의 간결한 열기 카드, 기능 홍보 목록 제거 |
| 탐색 도구를 상단에 모음 | 리더 미리보기의 동일한 큰 버튼 반복, typography | 검색·페이지 이동·확대를 상단 작업 도구막대로 정리 |
| 책갈피와 보기 방식 분리 | 목적이 다른 기능이 한 버튼에 묶인 현행 코드 | 별도 목록 진입과 보기 방식 선택 대화상자 |
| 보조 행동의 테두리 축소 | 기존 색상 토큰과 도구 위계 | Flutter 텍스트 버튼, Windows 평상시 중립 버튼과 포커스·선택 테두리 |

파랑·중립 표면·시스템 글꼴·실제 문서 아이콘을 유지한다. 가짜 썸네일이나 장식 이미지는 추가하지 않는다. 작은 화면·큰 글자는 기존 문서 도구 메뉴를 유지하고 웹 파일 입력과 인쇄의 실제 HTML 클릭 경로를 보존한다. 빈 문서함과 즐겨찾기 없음, 파일 오류, Drive 동기화 상태는 기존 복구 행동을 유지한다. 이 항목은 앞선 큰 2열 소개 화면 규칙을 대체한다.
