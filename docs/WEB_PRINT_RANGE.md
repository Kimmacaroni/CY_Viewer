# 웹 인쇄

## 기본 흐름

인쇄 버튼 → 전체 페이지 자동 준비 → 앱 안의 인쇄 버튼 → 시스템 인쇄 창.
매번 새로 열면 전체 페이지가 기본이다. 현재 페이지와 직접 범위는 ‘범위 변경’에서 선택한다.
선택 범위는 원문 순서로 정렬하고 중복을 제거한다. 준비 중 닫을 수 있으며,
닫기·범위 변경·오류·2분 시간 초과 이후 늦게 도착한 결과는 현재 작업에 적용하지 않는다.
첫 대화상자부터 닫을 때까지 인쇄 진입을 중복 실행하지 않는다.

## 외부 화면 없는 웹 경로

PDF 원본에서 선택 페이지를 순서대로 PNG로 렌더링하고, 같은 HTML 문서의 인쇄 전용 영역에 넣는다.
모든 이미지 decode가 완료된 후 인쇄 버튼을 활성화한다. 사용자 클릭 안에서 window.print()를 직접 호출한다.
숨긴 PDF iframe, 새 PDF 탭, 외부 공유 메뉴는 기본 경로에서 사용하지 않는다.
인쇄 매체에서만 Flutter 화면을 숨기고 PDF 한 쪽당 A4 한 장(10mm 여백)에 비율을 유지해 배치한다.
인쇄 자료는 시스템 호출 직후나 afterprint 이벤트에서 제거하지 않는다. Safari의 비동기 인쇄를 고려해
사용자가 앱 인쇄 대화상자를 닫거나 범위를 바꿀 때 제거하고 Blob URL을 해제한다.

페이지 렌더링은 최대 150dpi, 총 6400만 픽셀을 목표 상한으로 해상도를 조절한다.
72dpi 미만이 필요한 큰 문서는 일부 페이지를 조용히 누락하지 않고 범위 축소 또는 원본 PDF 사용을 안내한다.
한 번에 한 페이지를 처리하며 임시 PDF 이미지와 Flutter 이미지는 즉시 해제한다.
벡터 인쇄보다 작은 글자의 선명도가 낮을 수 있다. 메모리 상한은 기기별 안정성을 보장하지 않는다.
원본은 변경하거나 서버에 전송하지 않는다.

‘인쇄가 안 되면 원본 PDF 열기’는 사용자가 선택하는 대체 경로다. 항상 전체 원본을 연다는 것을 표시한다.
Mac·Windows 네이티브 인쇄 코드와 버전은 바꾸지 않는다. 생성 번역 사전의 추가 문구는 웹 전용이다.

## 검증과 한계

위젯 테스트: 16쪽 전체 기본, 현재 쪽 변경, 재진입 시 전체 초기화, 외부 열기 자동 호출 없음,
준비 중 닫기와 늦은 결과 무시를 검사한다. 기존 범위 파싱·오류 테스트도 유지한다.
실제 PDF 엔진 테스트는 CY_PDFIUM_TEST_LIBRARY를 지정한 로컬에서 4쪽 PNG 생성과 중간 취소,
기존 선택 PDF 추출을 검사한다. 해당 라이브러리가 없는 CI에서는 실제 엔진 테스트만 명시적으로 건너뛴다.
자동 테스트와 웹 빌드는 iPad PWA의 AirPrint 창 표시·16장 출력 성공을 증명하지 않는다.
현재 기기 UI 연결은 잠긴 Mac 때문에 사용할 수 없어 실제 iPad와 브라우저 인쇄는 미검증이다.
