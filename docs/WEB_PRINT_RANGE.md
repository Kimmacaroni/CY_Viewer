# 웹 인쇄 범위

iPad 화면 제보에서는 16쪽 문서인데 인쇄 창에 1쪽만 나타났다. 기존 printing 패키지는 데스크톱 Safari로 감지한 브라우저에서 숨겨진 PDF iframe에 print()를 호출했다. 데스크톱 UA를 쓰는 iPad도 해당 경로에 들어갈 수 있다. 이 경로를 회피하는 웹 전용 수정이다. Mac·Windows 네이티브 앱 인쇄 코드는 변경하지 않는다.

1. 웹앱 인쇄에서 전체 페이지, 현재 페이지 또는 직접 범위를 선택한다.
2. `2-5, 8`은 원문 2·3·4·5·8쪽을 선택한다. 중복은 제거하고 원문 순서를 유지한다. 0, 전체 쪽 수 초과, 역방향 범위, 잘못된 문자는 거부한다.
3. PDF 엔진으로 선택 페이지를 별도 벡터 PDF로 복사한다. 화면 캡처로 한 쪽을 만들지 않으며 원본은 수정하지 않는다.
4. Safari·모바일은 준비 완료 후 사용자가 ‘PDF 열고 인쇄하기’를 누른다. PDF의 공유 메뉴에서 인쇄한다. 별도 클릭 안에서 새 탭을 열어 비동기 생성 후 팝업 차단을 피한다. 팝업이 차단되면 오류를 안내하고 재시도할 수 있다.
5. 나머지 데스크톱 브라우저는 선택된 PDF를 기존 인쇄 경로에 전달한다. 운영체제 인쇄창의 쪽 번호는 선택된 PDF 기준으로 다시 매겨진다.

한국어·영어 문구를 공용 번역 원본에서 갱신했다. 네이티브 생성 번역에 추가된 문구는 웹 전용이며 네이티브 동작 변경이나 별도 데스크톱 버전 배포는 없다.

## 검증

범위 파싱·오류, 전체/현재/직접 선택 UI를 위젯 테스트로 검사한다. 실제 PDF 테스트는 `CY_PDFIUM_TEST_LIBRARY`에 PDFium 동적 라이브러리를 지정해 `flutter test test/web_print_test.dart`로 실행한다. 라이브러리가 없는 CI에서는 해당 실제 PDF 테스트만 명시적으로 건너뛰며 나머지 회귀 검사는 실행한다. 로컬 실제 PDF 검증은 통과했다. 실제 iPad AirPrint 페이지 선택·프린터 출력 성공은 별도 기기 확인 대상이다.
